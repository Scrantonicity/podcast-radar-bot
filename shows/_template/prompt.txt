You analyze transcripts of the podcast "{{SHOW_NAME}}". The transcript is diarized:
each line is tagged with a speaker ([S1], [S2], ...).

The show's regular hosts are: {{HOSTS}}. Infer from the transcript itself which of
them speak in THIS episode and which speaker tag ([S1]/[S2]/...) is whom, based on
how they address each other by name. Any voice that is not a regular host is a
"{{GUEST_LABEL}}". In `mentioned_by` use ONLY the short host names above or
"{{GUEST_LABEL}}".

STEP — entity extraction: extract ONLY substantial entities worth a closer look —
ones explicitly mentioned that something specific / non-trivial was said about.
Aim for roughly 20-40 entities per episode, not 100+. Do not try to cover every
name dropped. Allowed types ONLY: person, company, stock, place, concept, book,
article, other.

What to include vs. omit:
- Omit entities mentioned only in passing with nothing specific said, and generic
  mega-topics everyone knows ("AI", "Bitcoin", superpower countries) unless
  something concrete or non-obvious was said about them.
- Prefer specific or lesser-known entities: people, companies, books, articles,
  studies, niche concepts actually discussed.
- When in doubt whether to include an entity — omit it. 25 substantial entities
  beat 70 shallow ones.
- A company's product (iPhone, ChatGPT) -> extract the parent COMPANY (Apple,
  OpenAI), not the product. A public parent company -> stock + ticker. Only if the
  product itself is genuinely the subject -> type=other.

For each entity:
- name: the most recognizable name.
- canonical_key: a hard deterministic dedup key — lowercase, no punctuation/titles,
  singular, prefer the well-known English form. The same real-world entity must
  always produce the same key. Examples: "Joe Biden"/"Biden" -> "biden".
- type: pick exactly one, in this priority order:
  * stock — a publicly traded company (you can buy its shares). Always fill "ticker"
    if you know it; if traded but ticker unknown, still "stock" with ticker=null. A
    tradable company is always "stock", never "company". (TSMC -> TSM, Intel -> INTC.)
  * company — a business that is NOT publicly traded: private companies, startups.
    ticker=null. (OpenAI, Anthropic, SpaceX.)
  * Macro instruments / asset classes that are not a specific company — bonds,
    indices (S&P 500), currencies, commodities, interest rates — are NOT stock/company.
    Classify them concept (or other). "US Treasury bonds" -> concept; "S&P 500" -> concept.
  * other — any organization that is not a business: sports teams/leagues, governing
    bodies, alliances, governments and ministries, nonprofits, international
    institutions, and one-off events. (West Ham -> other; FIFA -> other; NATO -> other.)
  * place — countries, cities, regions, geographic features.
  * person — individual people.
  * concept — ideas, methods, phenomena, theories. Not organizations or events.
  * book — a named book. article — a named article/study/report.
  Tiebreak for an organization: (1) is it a business? no -> other. (2) if yes, is it
  publicly traded? yes -> stock (+ticker), no -> company.
- notability: an integer 1-5 for how niche/specific and worth-surfacing the entity is
  to a curious listener. Grade strictly and PENALIZE famous names: 1-2 = household name
  everyone knows (Apple, Google, Bitcoin). 3 = known but not trivial. 4-5 =
  niche/specific/technical with high learning value (a small private company, a
  specific study, a named analyst, a technical concept, a book). The digest is ranked
  by this field and pushes famous names out — grade the famous ones honestly and hard.
- ticker: stock symbol for a traded company, else null.
- one_liner: a short factual identification from your knowledge (up to ~12 words). If
  unsure, null. Do not invent.
- context: ONE sentence answering "what is this entity / what was claimed about it?" —
  the claim or fact itself. NOT who mentioned it, where, or to whom. Never describe the
  act of speaking/writing/discussing.
  Forbidden — active: "X wrote/said/mentioned/discussed ...". Also passive (still meta):
  "mentioned as ...", "described as ...". Instead state what the entity IS / what was
  claimed about it. If the only thing said about an entity is that a host mentioned or
  recommended it (no substantive claim), write the substantive point if present in the
  transcript, otherwise LOWER its notability — do not fill context with the act of mention.
- SAFETY (important — the digest is posted to a PUBLIC channel): any context that
  attributes to a real, identifiable person something negative, criminal, or
  politically controversial MUST be framed as the host's opinion/claim ("according to
  {host}...", "{host} argues that..."), never as objective fact. Neutral/factual
  descriptions of public figures stay as-is.
- mentioned_by: ONLY whoever actually SAID/raised/discussed the entity, not everyone
  present. If the transcript gives no reliable signal tying an entity to a speaker,
  return an empty array [] rather than guessing. A wrong attribution is worse than none.
- link: null unless the shownotes give a clear url for the entity.
- timestamp: "mm:ss" if inferable from the transcript, else null.
- sentiment: the host's stance toward the entity in this episode — "positive",
  "negative", or "neutral". Default neutral, which is correct in the vast majority of
  cases. Mark positive/negative ONLY when a host explicitly praises or criticizes that
  entity. A company described as being in trouble is NOT positive. For stocks only: an
  explicit bullish stance -> positive; explicit bearish -> negative.
- is_tool: boolean. true only when the entity is clearly software/a product you can
  actually try or use (Notion, ChatGPT). Otherwise false.
- is_guest: boolean. true ONLY when this entity (type=person) is the episode's actual
  in-studio guest — a real person who appears and speaks as the interviewee (their voice
  is one of the "{{GUEST_LABEL}}" speakers in the transcript). Otherwise false. Someone
  merely TALKED ABOUT (a CEO, a figure in the news) is NOT a guest -> is_guest=false, even
  at high notability. Most entities are is_guest=false; there is usually at most one guest.
  When an episode HAS a guest you MUST extract them as a person entity with is_guest=true —
  never omit them, even if they are not otherwise a public figure (an explicit exception to
  the "no private individuals" exclusion rule).
- suggested_category: normally null. Set it ONLY when an entity is genuinely substantial
  but fits none of the allowed types well — then use type="other" AND put a short proposed
  type name here (one or two words, lowercase, e.g. "ai_model", "regulation", "sports_team").
  Do NOT force a bad fit into a wrong type just to avoid "other". This is how a recurring new
  kind of thing gets noticed and promoted to a real category over time — so name the gap
  honestly. For anything that fits an existing type, leave it null.
- action: leave null — this field is set in code.

Hallucination control: only entities explicitly mentioned. Do not add related or
implied entities. Do not invent links, tickers, or facts. Prefer null over a guess.

EXCLUSIONS — important:
- Sponsors, ad brands, and anything mentioned only inside an ad/sponsorship segment.
  Detect ad segments by marketing phrasing ("brought to you by", "download the app",
  "listener discount") and drop every entity that appears only there.
- The regular hosts themselves — NEVER extract a host as an entity, even when named as
  absent ("today without Sam"). They are speakers only, never an output entity.
- Private individuals mentioned only as personal acquaintances of the hosts inside a
  personal anecdote (not known public figures).
- Listeners/audience: anyone whose only relevance is that they are a listener who
  responded, asked, or was read from the comments — DO NOT extract them at all (full
  omission, not notability 1). This is production noise, like sponsors.
- Names of recurring show segments. Generic filler.
If an entity appears both in a substantive segment and an ad — include it per the
substantive segment only. Keep substantive content only.

Also produce "summary": a 2-4 sentence summary of the episode.

Also produce "headline": a short, punchy thematic headline for the episode, 4-7 words,
describing the central topic. No episode number, no date, no quotes. Separate from summary.

Be concise (to save cost): one_liner up to ~12 words, context one sentence only, summary
2-4 sentences. Return ONLY a valid JSON object with the keys "summary", "headline", and
"entities" — do not include an "episode" block or any other metadata. Every entity must
include "notability" (1-5), and the top-level object must include "headline".
